# v1.26.0：质量分数历史与 CPR 3.50.0 适配

评分引擎已移植为 Rust。安装包不再包含 Python/NumPy，首次检测不再解出约 91 MB 的运行时，也不需要可执行临时目录。挑战、样本校验、候选概率及指纹库更新保持原有契约；旧报告继续保留原评分。

订阅标签与主项目统一，使用宿主显示名称及套餐颜色，支持 API / CPR 标记。账户列表默认只显示 GPT 系列（OpenAI/Codex），可切换全部提供方；定时订阅筛选保留已保存的原始套餐 ID。

状态：本地测试包，已由 [1.26.1](v1.26.1.md) 接续，未公开发布。宿主范围：`>=3.50.0,<3.51.0`。平台：Linux x86_64 / ARM64（aarch64），glibc 2.36+。

发布者为 `sirly`（CPR 标识字段仅允许小写），作者为 `Sirly`。新插件 ID：`sirly.modeltrace-health`。

账户列表将「历史记录」和「最新检测结果」分为独立两列，左侧以 uptime 风格展示质量历史，每个色块代表一次检测，最多展示最近 20 次。质量分数为目标模型概率 × 100：≥90 分为绿色，10–<90 分为黄色，<10 分为红色；悬停查看详情，点击打开当次报告，支持键盘导航。检测历史列表将「质量分数」和「最高候选」分列显示，报告同步显示分数。

目标模型按当次请求模型及保存的别名映射确定，使用最后一轮候选概率。旧记录直接派生分数，更新当前配置不会改写历史；未完成、失败或目标候选缺失时显示无分数。现有降智判定与账户处理规则不变，历史仍受每账户保留条数与宿主容量限制。完整规则见[使用指南](../usage.md#质量分数历史)。

SDK 与官方打包工具固定至 [CPR v3.50.0](https://github.com/zyycn/codex-proxy-rs/releases/tag/v3.50.0) 提交 `68b297fc8888e359db01deb5cc59640739be5ce6`。对照 v3.49.0，插件 SDK、官方打包器及管理桥接源码未变，继续使用 manifest v2、RPC v7、管理能力 v2 和维护能力 v1。

新版宿主将账户额度字段 `quotaLimits` / `quotaLimitsSupported` 替换为 `quotaSettings` / `quotaSettingsSupported`，支持每个额度桶的上限和预热设置。插件不读写这些字段，自动停用和移组仍只提交 `enabled` 或 `groupIds`，省略额度字段以保留宿主设置，无需修改业务代码。

URL 子路径部署由宿主管理页面处理。插件前端使用宿主桥接与相对资源路径，后端管理请求走宿主内部 HTTP 分派，继续使用 `/api/admin/...`，无需在插件中配置部署前缀。

私有状态 schema 不变。由于发布者变化，旧 `personal.modeltrace-health` 不能按同一插件直接升级：需安装新插件并导入旧版配置 JSON，历史及在线指纹库不会自动迁移。相同插件 ID 的后续版本仍支持同实例升级。发布时两种架构的预期包名如下，实际附件以 Release 为准：

| 宿主架构 | 安装包 |
| --- | --- |
| x86_64 | `sirly.modeltrace-health-1.26.0-x86_64-unknown-linux-gnu.tar.gz` |
| ARM64 | `sirly.modeltrace-health-1.26.0-aarch64-unknown-linux-gnu.tar.gz` |
